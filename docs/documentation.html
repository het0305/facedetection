1. Quick facts

What it does
A camera screen (kiosk) recognizes a registered person, checks they are a real live person (not a photo/phone), and records one attendance per person per day.
Who uses it
Person — stands in front of the kiosk.
Admin — registers people, views/export attendance, manages kiosks.
PartTechnologyFolderRuns on
Frontend (website)React 19, react-router 7frontend/http://localhost:3000
Backend (API)Node.js, Express 5backend/http://localhost:5000
DatabaseMongoDB (Mongoose 8)—mongodb://127.0.0.1:27017/faceattendance
Face AI@vladmandic/face-api on TensorFlow.js (WASM)backend/src/servicesinside the backend
Anti-spoof AIMiniFASNet ONNX models + onnxruntime-nodebackend/models/antispoofinside the backend

The 4 AI steps (remember "D-E-M-L")

D Detect
Find faces in the frame (SSD MobileNet v1) + 68 face landmarks.
E Embed
Turn the face into 128 numbers ("face fingerprint").
M Match
Compare with registered people. Distance must be small and clearly better than 2nd best.
L Liveness
Anti-photo model + "turn your head" challenge.

Golden rules of this project

  • Unsure = do not mark. "Unable to verify identity" is always better than marking the wrong person.
  • Server decides everything. The browser only shows the camera and messages.
  • No face photos are stored. Only encrypted 128-number templates.
  • One record per person per day — guaranteed by the database (unique index).

2. How to run

Before you start: MongoDB must be running (on Windows it runs as a service automatically).
Terminal 1 — Backend 
cd C:\Users\vicus\Desktop\facedetection\backend
npm start
Wait for: Server listening, port 5000
Terminal 2 — Frontend 
cd C:\Users\vicus\Desktop\facedetection\frontend
npm start
Wait for: Compiled successfully

Then open http://localhost:3000. Stop a server with Ctrl + C.

PageURLWho
Homehttp://localhost:3000Everyone
Admin consolehttp://localhost:3000/adminAdmin (username admin + your password)
Kiosk (camera)http://localhost:3000/kioskActivated device

One-time setup (new computer / fresh clone)

cd backend
npm install
copy .env.example .env          # fill JWT_SECRET and BIOMETRIC_KEY (commands inside the file)
npm run create-admin -- admin   # asks for a password (10+ chars, letters + numbers)
cd ..\frontend
npm install

Production (single server)

cd frontend  &&  npm run build
cd ..\backend  &&  set NODE_ENV=production  &&  npm start     # everything on :5000 (use HTTPS)

Browsers allow the camera only on HTTPS or localhost.

5. Workflow B — register a person

Admin console → Register user. Page: pages/admin/RegisterStudent.js.

1
Enter details
Full name + employee/roll number. Checked instantly in the browser and again on the server.
Frontend: utils/format.js (validateName, validateRollNo) · Backend: routes/schemas.js
2
Guided face capture (5 photos)
Look straight → turn slightly left → turn slightly right → straight → straight.
Each live frame is sent to the server; a photo is auto-captured after 2 good frames in a row.
Frontend: components/FaceCapture.js, hooks/useCamera.js → POST /api/students/check-sample → enrollmentService.checkSample → faceAnalysis → quality.checkPose, liveness
3
Live guidance messages
"Move closer to the camera", "Improve lighting", "Please look directly at the camera", "Only one person should be visible"...
Backend: services/quality.js (MESSAGES)
4
Review & save
All photos are sent together. Server re-checks every photo, makes sure all are the same person, and makes 128-number templates.
POST /api/students → routes/students.js → enrollmentService.buildSamples → matcher.maxPairwise
5
Duplicate-face check
If this face already belongs to another registered person → warning "A similar face is already registered. Please verify before continuing." Admin can cancel or confirm (logged in audit).
gallery.findSimilar (DUPLICATE_FACE_THRESHOLD) · audit.js
6
Encrypt & store
Templates encrypted with AES-256-GCM and saved. Photos are thrown away. Gallery reloads.
utils/biometricCrypto.js → models/Student.js → gallery.invalidate
7
Done
"Face registered successfully."
Re-register a face later: Users → open person → "Re-register face" (PUT /api/students/:id/face). Same checks, replaces old templates.

6. Workflow C — mark attendance (kiosk)

Page pages/Kiosk.js sends a frame every ~0.3 s to POST /api/kiosk/scan. The server keeps a scan session (services/scanSession.js) — a state machine that decides step by step.

1
Looking for face...
No face → keep scanning. More than one face → "Please ensure only one person is visible." and progress resets.
faceAnalysis.analyzeFrame → faceEngine.detect
2
Quality check
Too small / blurry / dark / bright / turned → guidance message, frame not counted.
quality.assessQuality · faceGeometry.headPose
3
Passive liveness (anti-photo)
Two MiniFASNet models score each good frame (0–1). Mean of 3+ frames must be ≥ 0.6. Two frames < 0.2 → "Unable to confirm a live person."
liveness.passiveScore · faceEngine.antispoofInput
4
Verifying identity...
128-number template compared with everyone. Accept only if distance ≤ 0.5 and 2nd-best person is ≥ 0.06 further. Same person on 3 frames in a row (5 if not high-confidence). Unknown 4 times → "Face not recognized."
faceEngine.descriptor → gallery.match → matcher.match
5
Challenge
Random: "Please turn your head slightly to your left/right." (screen is mirrored: your left = screen left). Then "Now look back at the camera." 10 s limit.
liveness.Challenge · randomChallengeType
6
Confirm
One more straight frame must match the same person. A different person at any time → "Unable to verify identity."
scanSession (CONFIRM phase)
7
Record attendance
Insert one record for today (time zone APP_TIMEZONE). If already there → "Attendance already marked today." Late after LATE_AFTER time (optional).
attendanceService.markAttendance → models/Attendance.js (unique studentId + dayKey) · utils/time.js
8
Show result, then continue
Green card: name, ID, time, status. After ~4 s the kiosk scans for the next person.
Kiosk.js (result card)
Kiosk colourMeaning
GreyLooking for face
BlueVerifying / checking liveness (progress bar)
AmberFix something (lighting, distance, one person only)
VioletDo the challenge (arrow shows direction)
GreenAttendance marked
RedNot recognized / not live / failed — nothing recorded

15. Security in short

Login
  • bcrypt password hash
  • httpOnly + SameSite=Strict cookie (8 h)
  • 5 wrong tries → locked 15 min
  • Logout revokes the token on the server
Kiosk
  • Own device token, only for scanning
  • Cannot open admin pages
  • Revoke anytime in Settings
Requests
  • CSRF header + Origin check
  • zod validation (no NoSQL injection)
  • Rate limits, 20 kB JSON limit
  • Helmet headers + CSP
Uploads
  • Memory only, never saved to disk
  • Magic-byte check (real JPEG/PNG)
  • Size + resolution limits
Biometric data
  • AES-256-GCM encrypted templates
  • Never sent to the browser
  • No face photos stored
Logs & audit
  • Passwords/tokens/face data auto-hidden
  • Audit log: register, delete, export, overrides, failed logins, spoof attempts
Limits (be honest): one normal webcam cannot stop 100% of attacks (e.g. high-quality 3D masks or hacked video input). It stops printed photos, phone/monitor screens and simple replays.

Testing checklist (manual, on the real camera)

  • Registered person → marked in ~3–5 s; again → "already marked"
  • Unregistered person → "Face not recognized", nothing saved
  • Printed photo / phone photo / video → never marked
  • Two people in view → "only one person"
  • Stand 30 s in front of camera → still exactly one record
  • Dark room, glasses, far/near → guidance, never a wrong name
