1. Transfer learning in simple words

Transfer learning = reuse a model that already learned one big job, for a new related job, instead of training from zero.

Easy example: learning to drive

Someone who can already ride a bicycle knows balance, traffic rules and steering.
→
They learn a motorbike much faster. They transfer what they already know.

Same idea for faces

A model was trained on millions of faces of other people. It learned what makes faces different: eye shape, nose, jaw, spacing.
→
We reuse that model to recognize our own users, people it has never seen, without training it again.

Without vs. with transfer learning

Remember: "Learned once, reused everywhere." The heavy learning was done by the model's authors. We only use the knowledge.

2. The two types — and which one we use

Type 1 — Feature extraction (we use this)
  • Use the pre-trained model exactly as it is (frozen).
  • Take its output (the "features") and use it for your task.
  • No training at all.

Our project: the ResNet gives 128 numbers per face. We compare those numbers to find who it is.

Type 2 — Fine-tuning (NOT used)
  • Take the pre-trained model and train it a little more on your own data.
  • Changes the model's weights.
  • Needs a dataset, time and usually a GPU.

Our project never changes any model weights.

Picture of feature extraction

Face photo→Pre-trained model (frozen, never changes)→128 numbers ("face fingerprint")→Compare distance→Who is it?
Memory trick: "Freeze & Use". We freeze the model (no training) and use its output. That is feature extraction.

3. Is transfer learning used in my project?

Yes. The project uses transfer learning by feature extraction. It uses 5 pre-trained models without any fine-tuning. No model is trained anywhere in the project.
QuestionAnswer
Is any model trained in the project?No. All models come pre-trained.
Is fine-tuning done?No. Model weights never change.
Where is the "transfer"?Knowledge learned from other people's faces is reused to recognize our users, and to detect faces, face points and fake faces.
Where are the models?Face models: inside the npm package @vladmandic/face-api (folder node_modules/@vladmandic/face-api/model). Anti-spoof models: backend/models/antispoof/.
Which code loads them?backend/src/services/faceEngine.js (face models) and backend/src/services/liveness.js (anti-spoof models). Both load once when the server starts.
What runs them?TensorFlow.js (WASM backend) for face models; onnxruntime-node for anti-spoof models.

What our project adds on top (our own logic, not learned)

  • Quality rules: face size, blur, lighting, pose (quality.js)
  • Matching rule: distance ≤ 0.5 and 0.06 better than the 2nd-best person (matcher.js)
  • Decision steps: 3 stable frames, head-turn challenge, confirm (scanSession.js)
  • Attendance rules: one record per person per day (attendanceService.js)
Easy line: "The models give the knowledge; our code gives the rules."

7. Model 3 — Face Recognition ResNet ("The Fingerprinter")

3128-D face descriptor (the main transfer-learning model)

JobTurn a face into 128 numbers (a "face fingerprint" / embedding). InputThe aligned face (using Model 2's points), resized to 150×150. Output128 decimal numbers. TypeResNet (deep network with "shortcut" connections), trained with metric learning: the same person's faces → close numbers, different people → far apart. Fileface_recognition_model.bin (6.4 MB) Loaded infaceEngine.js → init() Called infaceEngine.js → FrameImage.descriptor() Numbers used bymatcher.js (compare), gallery.js (all users in memory), biometricCrypto.js (encrypt before saving)

How recognition works with it

New face→ResNet → 128 numbers→distance to each registered person→smallest ≤ 0.5?→0.06 better than 2nd?→Same on 3 frames?→Identified
PlaceWork done
RegistrationMakes 128 numbers for each of the 5 photos → checks they are the same person → checks no one else already has this face (duplicate check) → encrypted and saved.
KioskMakes 128 numbers for each good frame → compared with all saved templates → name or "Face not recognized".
TrackingNumbers must stay similar inside one session, so a different person stepping in resets progress.
Duplicates tabCompares everyone with everyone to find the same person registered twice.
Why this is the heart of transfer learning: it was trained on thousands of other people, yet it works for your users, because it learned how to describe any face, not just the people in its training set.

8. Models 4 & 5 — MiniFASNetV2 + MiniFASNetV1SE ("The Guards")

4+ 5Passive anti-spoofing (liveness)

JobDecide if the face is a real live person or a fake (printed photo, phone or monitor screen). Input80×80 crop around the face. Guard 1 (V2) uses a crop 2.7× the face; Guard 2 (V1SE) uses a wider 4.0× crop, so it also sees the edges of a phone or paper. Output3 scores → softmax → "real" probability (0–1). We average both guards. TypeMiniFAS = "Mini Face Anti-Spoofing" network, very small and fast (~5 ms). SE = "Squeeze-and-Excitation" attention blocks. Filesbackend/models/antispoof/MiniFASNetV2.onnx, MiniFASNetV1SE.onnx (1.7 MB each) Loaded inliveness.js → init() using onnxruntime-node Called inliveness.js → passiveScore(); crop made by faceEngine.js → antispoofInput() SettingsLIVENESS_THRESHOLD = 0.6 (average needed), LIVENESS_HARD_FAIL = 0.2

What they do at that place

PlaceWork done
KioskScore every good frame. Average of 3+ frames must be ≥ 0.6. Two frames below 0.2 → "Unable to confirm a live person." and a security event in the audit log.
RegistrationEach photo must be live, so nobody can register someone using their photo.

Two layers of liveness

Passive (the models)
Looks at texture, glare, edges and moiré patterns of screens/paper. No action needed from the user.
Active (our code + Model 2)
"Turn your head slightly left/right". The landmark points prove the head really moved.
Transfer here: the Guards learned "real vs. fake" from Minivision's dataset of real and attack photos. We reuse them unchanged.

Measured on your own webcam: real faces scored 0.89–0.998. Attack scores must still be measured with npm run evaluate-liveness.

11. Registration is NOT training

Common mistake: "When I register a person, the model learns their face." Wrong. The model does not change at all.
What really happens at registration
  1. The frozen Fingerprinter reads the 5 photos.
  2. It outputs 5 × 128 numbers.
  3. The numbers are encrypted and saved in MongoDB (students.samples).
  4. They are loaded into memory (gallery.js) for fast matching.
What really happens at the kiosk
  1. The same frozen model makes 128 numbers for the new face.
  2. matcher.js measures the distance to every saved person.
  3. Small enough and clearly the best → that person.
Training (not in our project)Registration (our project)
Model weightsChangeNever change
TimeHours/days~2 seconds
Stored resultA new model file128 numbers per photo
Delete a personRetrainDelete their numbers
Easy line: "Registration stores a face fingerprint; it does not teach the model."

12. Why transfer learning here (benefits & limits)

Benefits
  • No big dataset needed: 5 photos per person.
  • No GPU: runs on a normal laptop CPU (~0.3–0.4 s per frame).
  • Instant new users: no retraining.
  • Proven accuracy: the models were trained and tested by their authors on large datasets.
  • Privacy: we store only 128 numbers, not photos.
  • Small: all 5 models together ≈ 16 MB.
Limits (be honest)
  • The models were trained on other data; accuracy on your camera/lighting must be measured (npm run evaluate).
  • Very similar faces (twins) can look alike → our margin rule answers "Unable to verify identity" instead of guessing.
  • One normal webcam can't stop every attack (e.g. 3D masks).
  • Fine-tuning could improve accuracy, but needs a labelled dataset and a GPU.

13. Viva / exam questions & answers

Q1. What is transfer learning? Reusing a model trained on one large task for a new related task, instead of training from scratch. Q2. Is transfer learning used in your project? Yes, as feature extraction. Five pre-trained models are used without fine-tuning. Q3. Which type of transfer learning? Feature extraction (frozen models). No fine-tuning. Q4. Name the models. SSD MobileNet v1 (detection), Face Landmark 68 (landmarks), ResNet face recognition (128-D embedding), MiniFASNetV2 and MiniFASNetV1SE (anti-spoofing). Q5. Which model does the actual recognition? The ResNet face recognition model. It outputs a 128-number embedding, compared with Euclidean distance. Q6. Do you train the model when a user registers? No. Registration only stores the user's embeddings (encrypted). The model never changes. Q7. How do you decide who the person is? Smallest distance must be ≤ 0.5, at least 0.06 better than the second-best person, and the same on 3 consecutive frames. Q8. How do you stop photo attacks? Two MiniFASNet models (passive liveness) plus a head-turn challenge verified with the 68 landmarks. Q9. Why not train your own model? That needs millions of labelled faces, GPUs and weeks. Transfer learning gives proven accuracy with 5 photos per user on a normal CPU. Q10. What libraries run the models? TensorFlow.js (WASM backend) through @vladmandic/face-api for models 1–3; onnxruntime-node for the MiniFASNet models. Q11. What is an embedding? A list of numbers that describes a face so that the same person gives close numbers and different people give far numbers. Q12. What is metric learning? The training method the ResNet authors used: pull the same person's embeddings together, push different people apart.
